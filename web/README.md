# Aboriginal Art Gallery - Web Frontend

Vue 3 single-page client for the Aboriginal Art Gallery API. Public visitors
browse artists, artifacts, and tribes (including each tribe's territory drawn
on a map); signed-in admins get the curatorial CRUD and the user-management
screen.

This is the frontend only. Backend, domain, and architecture docs live at the
[repository root](../README.md) and in [`../docs`](../docs).

## Stack

- **Vue 3** with `<script setup>` SFCs and TypeScript
- **Vite** dev server and build
- **Pinia** stores (one per context + an auth store)
- **Vue Router** with an admin route guard
- **Tailwind v4** (`@theme`), catalog/archive visual design
- **axios** with request/response interceptors (Bearer token, 401 handling)
- **Leaflet** for the tribe territory map (free CARTO tiles, no API key)
- **openapi-typescript**: API types are generated from the backend's OpenAPI
  spec, never hand-written

## Prerequisites

- Node + `pnpm` (or `npm`)
- The API running at `http://localhost:8080` (see the root README). Type
  generation reads the live spec, so the API must be up for `generate:types`.

## Setup

```bash
pnpm install
pnpm run generate:types   # reads http://localhost:8080/api-docs/openapi.json
pnpm run dev              # http://localhost:5173
```

Other scripts:

```bash
pnpm run build            # vue-tsc type-check + production build
pnpm run preview          # serve the production build locally
pnpm run generate:types   # regenerate src/api/generated.ts after any API change
```

If the API base URL differs, set `VITE_API_URL` (defaults to
`http://localhost:8080`).

## How the API types stay in sync

The frontend never hand-writes API types. The chain is one direction and
each step is machine-checked:

```
DB schema -> Rust handlers/models -> OpenAPI spec -> generated.ts -> types.ts -> stores/views
```

`src/api/generated.ts` is generated by `pnpm run generate:types`.
`src/api/types.ts` is a thin facade that re-exports flat names (`Artist`,
`TribeInput`, ...). After any backend model or route change: rerun the API,
then `pnpm run generate:types`. A mismatch becomes a TypeScript build error,
not a runtime surprise.

## Auth flow

- `auth` store holds the JWT + user, persisted to `localStorage`.
- The axios request interceptor attaches `Authorization: Bearer <token>`.
- The response interceptor turns any 401 into logout + redirect to `/login`
  (skipped on the login request itself to show inline errors).
- Routes flagged `meta.requiresAdmin` are gated by a `beforeEach` guard:
  unauthenticated users go to `/login?redirect=...`, authenticated
  non-admins go home.
- Admin-only UI (mutation controls, the `users` nav link and page) is hidden
  unless the session is an admin. This mirrors the backend for UX only; the
  server is the real authority.

## Structure

```
src/
  api/
    generated.ts   GENERATED from the OpenAPI spec (do not hand-edit)
    types.ts       flat re-export facade over generated.ts
    client.ts      axios instance + Bearer / 401 interceptors
  stores/          Pinia: artists, artifacts, tribes, users, auth
  views/           one list/detail/create/edit per context + Home/Login/Register/Users
  components/
    AppShell.vue   header nav, breadcrumb, sign-out, admin gating
    *Form.vue      shared create/edit forms
    TerritoryMap.vue  Leaflet map of a tribe's GeoJSON territory
  router/          routes + admin guard
  style.css        Tailwind v4 theme (catalog/archive palette + type)
```

## Notes

- The tribe detail page shows the territory two ways: a Leaflet map and a
  collapsible raw-GeoJSON panel, both driven by the same value. Map tiles
  load from CARTO at runtime; offline, the basemap is blank but the polygon
  still draws.
- Territory polygons are coarse demo approximations, not authoritative
  cultural boundaries; the UI states this and renders an Acknowledgement of
  Country.
- No frontend test suite: this is a backend-focused task and the testing
  depth lives in the API. See the root README.
